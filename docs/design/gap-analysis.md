# Living World — Разбор пробелов и интеграции с RimWorld

Статус: **живой документ.** Собирает, что нам известно о реальных механиках
RimWorld и мод-экосистемы, чего наш дизайн ещё не учёл, и куда это ведёт. Каждый
факт снабжён источником, чтобы было понятно, **откуда это** и что перепроверять
при смене версии игры.

## 1. Подтверждённые факты RimWorld (с источниками)

### Рейды и очки
Размер рейда определяется «очками» (points) от богатства + пешек колонии; очки
«покупают» рейдеров по стоимости pawnkind'а, а `maxPawnCostPerTotalPointsCurve`
не даёт дорогим пешкам собирать крошечные рейды.
→ Значит **число пешек ≠ points/100**: наша привязка (reserved vs generated) в
принципе не совпадёт точно — подтверждает необходимость reconciliation.
Источники: [Raid points](https://rimworldwiki.com/wiki/Raid_points),
[Wealth management](https://rimworldwiki.com/wiki/Wealth_management).

### WorldPawns и сборка мусора — КЛЮЧЕВОЕ
RimWorld уже хранит off-map NPC в `WorldPawns` и удаляет их GC: WorldPawn живёт
>1 года (5 лет для фракции игрока), **если не «важный»** — лидер фракции,
похищенный, участник каравана, зарезервирован квестом, есть труп, **или имеет
родственные связи / упоминания в логах**. Пешки со связями не удаляются почти
никогда → раздувание сейва.
→ Наш ledger — **параллельная** система населения. Хранить лёгкие записи и
материализовать по требованию — правильно. Но появляется риск **рассинхрона**
(см. §2.A).
Источники: [WorldPawns.cs (decompiled)](https://github.com/josh-m/RW-Decompile/blob/master/RimWorld.Planet/WorldPawns.cs),
[Pawns](https://rimworldwiki.com/wiki/Pawns).

### Фракции статичны; вымирание — нативно
Базовые фракции не расширяются и не основывают поселения. Уничтожение всех баз
фракции = её истребление (не шлёт рейды/квесты). Создание фракции в рантайме
ваниль не умеет — только моды (More Factions делает на руинах, ~10% шанс), с
оговорками по совместимости.
→ Наше **вымирание совпадает с ванилью**; **создание** фракций — ledger-first,
материализация за флагом.
Источники: [Factions](https://rimworldwiki.com/wiki/Factions),
[More Factions](https://steamcommunity.com/sharedfiles/filedetails/?id=3702515214).

### «Wild Person» и арайвал-инциденты — готовый «дрифтер»
В ванили уже есть безфракционный человек (Wild Person), а также Wanderer joins,
Refugee chased, Transport pod crash — точки прихода новичков.
→ Наш «космический кран» **материализуется через них**, не через новый спавн.
Источник: [Events](https://rimworldwiki.com/wiki/Events).

### Дипломатия
Три уровня (враг/нейтрал/союзник), естественный распад goodwill, пираты -100
навсегда, скрытые фракции (мехи, инсекты, Ancients, культ Хоракса, орбитальные
сборщики) недипломатичны.
Источник: [Faction Relationships](https://rimworld.fandom.com/wiki/Faction_Relationships).

### Рабство (Ideology DLC)
Раб = пленник с волей 0 (или recruitment inspiration); подавление/ребеллии;
Emancipate даёт goodwill исходной фракции; есть работорговцы.
→ Готовые хуки для §8 (плен/рабы) и §9 (возврат пленника) спеки, **но за DLC**.
Источник: [Slavery](https://rimworldwiki.com/wiki/Slavery).

### Мехи и жуки — не население
Мехи — древние машины неизвестного происхождения; инсектоиды — ват-выращенные с
планеты Сорн для войны с мехами.
→ Наш разрез «людей бэкаем, мехов/жуков — ваниль» лорно верен.
Источники: [Mechanoids](https://rimworldwiki.com/wiki/Mechanoids),
[Insectoids](https://rimworldwiki.com/wiki/Insectoids).

### Производительность
Игра однопоточная; TPS падает уже за ~20 пешками / 200 животными; главные приёмы
оптимизации — реже тикать (time-dilation, throttled scanning) и кэшировать
производные.
→ Глобальная симуляция обязана быть планировщик + агрегаты, без per-citizen LINQ
в горячих путях. Приёмы для нашего глобального слоя (из перф-модов):
- **адаптивная time-dilation** — тикать когорты/регионы редко, частоту
  масштабировать по релевантности (близость к игроку, бой) **и по тому, насколько
  сущность реально меняется**: тихий регион — редко, активная война — чаще.
  RocketMan гонит животных 60→5 Гц; Missile Girl «учится», как часто пересчитывать;
- **кэш производных** — сила фракции, доступность, пулы; не пересчитывать каждый
  тик (RocketMan «убирает 90% ванильных пересчётов»);
- **предрасчёт world-reachability** — если добавим движение армий/караванов;
- **никаких дорогих per-tick lookup'ов** — конкретный анти-паттерн: ванильная
  яйцекладка тикала пищевые нужды каждый тик (Red's Performance Fixes её чинит).
  Наш аналог — не гонять LINQ по всем гражданам/связям в горячих путях.

Источники: [Perf guide](https://steamcommunity.com/sharedfiles/filedetails/?id=2894425236),
[RocketMan (time-dilation, кэш, reachability)](https://steamcommunity.com/sharedfiles/filedetails/?id=2479389928),
[Missile Girl (поддерж. форк RocketMan, адаптивный кэш, open-source)](https://steamcommunity.com/sharedfiles/filedetails/?id=3712928623),
[Red's Performance Fixes (пример: убирает per-tick lookup в яйцекладке)](https://steamcommunity.com/sharedfiles/filedetails/?id=3343465955),
[Rim73 (референс приёмов, заброшен)](https://steamcommunity.com/sharedfiles/filedetails/?id=2573814850).

### WorldPawns-блоат подтверждён на практике
Мод **RuntimeGC** существует именно чтобы вручную **вырезать лишние world pawns**,
уменьшать сейв и **чинить ошибки отношений/лидеров фракций** — игроки репортят
TPS 20→900 после чистки. Это прямое доказательство углов A и C.
→ (1) Наш ledger — «анти-блоат»: компактные записи вместо тысяч полных пешек, но
**только при компактной сериализации** (§2.C). (2) Нельзя полагаться на выживание
RimWorld-пешки: GC/RuntimeGC её вырежет → привязка по `thingIDNumber` протухнет
(§2.A). Ledger — источник истины. (3) Наш `WorldComponentTick` не должен плодить
world pawns, которые RuntimeGC потом режет.
Источник: [RuntimeGC In-Game Cleaner](https://steamcommunity.com/sharedfiles/filedetails/?id=962732083).

## 2. Что мы упустили — по углам

### A. Интеграция и рассинхрон
- **Двойная система населения** (ledger ↔ WorldPawns): нужен контракт «кто
  авторитет + жизненный цикл». Привязка по `thingIDNumber` ненадёжна при
  GC/переспавне → нужна карта идентичности, переживающая материализацию.
- **Плен игроком = рассинхрон:** захваченный рейдер — и RimWorld-пленник, и наш
  `WorldCitizen (Prisoner)`. Вербовка/порабощение/эмансипация меняют его в ванили,
  а ledger не знает → нужен обратный sync (событие в ledger). Emancipate → goodwill
  исходной фракции — хук для «пленник вернулся к своим» (§9).
- **Трупы/родственники раздувают ванильный сейв** даже при лёгких наших записях →
  давать RimWorld собирать материализованных рейдеров в GC, храня только запись.

### B. Пробелы спеки
- **DLC-гейтинг:** рабство = Ideology; дети/гены/аджинг = Biotech; сущности =
  Anomaly; титулы/Empire = Royalty. Модель обязана деградировать без них (fail-open).
- **BioTech, селекция и инкубаторы:** скрещивание животных, селекция культур,
  эмбрионы, инкубаторы и будущая работа с xenotype не должны быть отдельной
  фабрикой пешек. Это должны быть ledger-проекты, завязанные на когорты
  животных/культур, технологии, специалистов, питание, электричество, медицину,
  компоненты, риски и intel. Подробный baseline: [BioTech, Breeding And Selection](biotech-breeding-and-selection.md).
  Поперечный анализ зависимостей и рисков: [BioTech Systems Analysis](../research/biotech-systems-analysis.md).
- **Дипломатия/goodwill не в модели** — пока пиггибэкаем ваниль; мировые войны
  (Stage 6) потребуют своей модели отношений.
- **Скрытые/безбазовые людские фракции** (Ancients — люди, но без баз): гейт
  «есть население/поселения» их отсекает (pass-through) — перечислить в тестах.
- **Квесты** (refugee/hospitality) — ещё канал прихода, не отражён.

### C. Производительность и масштаб
- **Наш XML-ledger не масштабируется** до 20k–100k: `WorldStateCodec` пишет по
  элементу на сущность → гигантский сейв и долгая загрузка. Для глобального слоя —
  **когорты/агрегаты**, не поимённые записи.
- Глобальная симуляция — планировщик + агрегаты; никаких per-citizen проходов в
  горячих путях (уже мелькал O(citizens×links) в биндинге).
- **Перенять приёмы перф-модов нативно:** time-dilation (когорты/регионы тикают
  редко, частота по релевантности) + кэш производных (сила фракции, пулы) — не
  зависеть от RocketMan, но и не конфликтовать с ним.
- **Совместимость с RocketMan/RuntimeGC:** не плодить world pawns, которые
  RuntimeGC режет; не полагаться на пер-тик пересчёты, которые RocketMan кэширует.
  Правильный ledger **уменьшает** WorldPawns-блоат, а не добавляет.

### D. Совместимость (это личный модлист проекта!)
- **Rim War активен** и делает почти то же (движущиеся варбанды, очки поселений,
  экспансия, world-объекты, патчи похожих инцидентов) → без адаптера **двойное
  вождение** фракций. Приоритет №1.
- **VFE-Settlers/Insectoids/Mechanoids** распространены; VFE-Insectoids даёт жукам
  базы и рейды — humanlike-гейт их пропускает (проверить).
- **Несколько модов патчат генерацию рейдов** → нужен тест «не ломаемся, если рейд
  уже перехвачен другим модом».
Источники: [Rim War](https://steamcommunity.com/sharedfiles/filedetails/?id=2222935097),
[VFE-Insectoids](https://steamcommunity.com/sharedfiles/filedetails/?id=2149755445).

### E. Геймплей / баланс / UX
- **Storyteller-ожидание:** переформируя рейды, не спорить с замыслом рассказчика —
  всё должно быть аддитивным.
- **Баланс снежного кома:** выбитые фракции перестают нападать → кран + мехи/жуки
  держат напряжение; нужна настройка.
- **Легибельность последствий:** мир должен быть *виден* живым (тренды населения /
  силы фракций).

### F. Ещё пропущенные системные слои
- **Инфраструктура и здания:** лаборатории, больницы, склады, дороги, мосты,
  электросети, оборона и жильё должны давать capacity. Сейчас многие формулы
  рискуют зависеть только от населения/ресурсов.
- **Образование и специалисты:** врачи, исследователи, фермеры, генетики,
  инженеры, дипломаты и офицеры должны быть ограничителем сложных систем.
- **Болезни, санитария и отходы:** плотность населения, инбридинг, фермы,
  лаборатории, токсичные биомы и торговые пути должны создавать эпидемии и
  экологическое давление.
- **Технологическое распространение:** фракции должны не только иметь tech tier,
  но и учиться, воровать, покупать, терять и скрывать технологии.
- **Логистика:** дороги, животные, транспорт, топливо, караваны, портовые/речные
  пути и погода должны ограничивать торговлю и войны.
- **Управление, законы и культура:** лидеры, наследование, стабильность,
  идеология, отношение к рабству/генетике и внутренние бунты нужны для
  правдоподобного мира.
- **Руины и восстановление:** уничтоженное поселение должно оставлять руины,
  ресурсы, претензии, беженцев и шанс восстановления, а не просто исчезать.

## 3. Кастомный сторителлер как точка интеграции

RimWorld сторителлеры собираются из `StorytellerComp` (категории событий:
`ThreatBig`, `AllyArrival`, `Misc`…) и правил вроде `CompProperties_CategoryMTB`
(mean-time-between). Это **нативная** точка расширения.
Источники: [AI Storytellers](https://rimworldwiki.com/wiki/AI_Storytellers),
[Custom Comp Classes](https://rimworldwiki.com/wiki/Modding_Tutorials/Custom_Comp_Classes).

**Почему это привлекательно для нас:**
- **Проще:** вместо Harmony-патчей на `TryResolveRaidFaction`/`TryGenerateRaidInfo`
  мы **добавляем свой incident** (`LivingWorld_FactionRaid`), который тянет
  рейдеров из ledger'а, и управляем его выбором через свой `StorytellerComp`.
  Меньше поверхности конфликтов.
- **Быстрее:** логика работает на **частоте инцидентов** (редко, по MTB), а не в
  горячих путях каждый тик/пешку (сейчас у нас патч на `Pawn.DeSpawn` висит на
  каждом деспавне). Часть sync-хуков активной карты останется, но горячих —
  меньше.
- **Гармоничнее:** сторителлер спроектирован сменяемым; это «санкционированная»
  игрой точка контроля темпа.

**Компромисс:** свой сторителлер **заменяет** выбранного игроком (Cassandra/Randy).
Игроки к ним привязаны. Поэтому два уровня:
1. **Аддитивно (рекомендуется как первый шаг):** свои ledger-инциденты + свой
   `StorytellerComp`, который можно подмешать; ванильные рейды приглушаются, а не
   вырезаются. Совместимо с любым рассказчиком.
2. **Свой рассказчик (опционально):** «Живой мир» как отдельный выбор для тех, кто
   хочет полностью ledger-управляемый темп; можно настраивать под стили пейсинга.

Это **не отменяет** обратный sync активной карты (смерти/плен), но резко сокращает
инвазивность и горячие патчи — прямой ответ на цели «проще + быстрее».

## 4. Приоритеты (что добавить/сделать)

1. **Контракт ledger ↔ WorldPawns** + обратный sync плена/вербовки/рабства.
2. **Свой incident + StorytellerComp** (аддитивно) вместо патчей генерации рейдов —
   проще и производительнее; свой рассказчик — опционально поверх.
3. **DLC-гейтинг** (fail-open без Ideology/Biotech/Royalty/Anomaly).
4. **Компактная сериализация + когорты** для глобального слоя (иначе 100k недостижимо).
5. **Адаптер Rim War** — первоклассная совместимость (в модлисте проекта).
6. **Переиспользовать Wild Person / арайвал-инциденты** как материализацию крана.
