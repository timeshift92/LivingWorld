# Living World — Абсорбция Rim War: анализ эдж-кейсов и инвариантов

Статус: **предреализационный разбор рисков.** Проходит по всем фазам R1–R7
([rimwar-absorption.md](rimwar-absorption.md)) и перечисляет крайние случаи, режимы
отказа и как их закрыть — чтобы «всё было ок» до старта кода. Каждый пункт: **случай
→ обработка → что проверить тестом.**

Связано: [rimwar-absorption.md](rimwar-absorption.md), [population-flow.md](population-flow.md)
(§1 «ничто из воздуха»), [gap-analysis.md](gap-analysis.md) (§A GC, §C масштаб, §D
Rim War/совместимость), [simulation.md](../simulation.md).

## 0. Сквозные инварианты (держать во ВСЕХ фазах)

| # | Инвариант | Риск-случай | Обработка | Тест |
|---|---|---|---|---|
| I1 | **Консервация** («ничто из воздуха») | мощь/армия/бой фабрикуют людей | мощь = f(реального населения); потери боя списывают **реальных** граждан; армия — это владение существующими гражданами, не спавн | after-battle: Σ населения мира не растёт; убыль = сумме потерь |
| I2 | **Детерминизм** | RNG/`Rand`/время в Core | только seed-производные (`WorldSeed`+tick+id), стабильные сортировки `OrderBy(id)`; никаких `Rand`/`DateTime` в Core | двойной прогон одного seed → идентичный результат |
| I3 | **Fail-open** | RimWorld-слой падает/нет данных | worker/патч → ваниль без изменений; Core-исключение не всплывает в игру | worker с null-компонентом → декларирует «не могу», ваниль идёт |
| I4 | **Масштаб / горячий путь** | per-citizen LINQ в тике на 20k–100k | мощь и цели — **кэш-агрегаты**, пересчёт раз в день; когорты, не поимённо (§C) | нет `state.Citizens`-прохода вне дневного пути; бенч на 20k |
| I5 | **Back-compat сериализация** | старый сейв без новых полей | все новые поля (behavior, позиция армии, отношения) — `Look` с дефолтом; отсутствие = нейтраль | roundtrip старого снапшота без новых полей |
| I6 | **Идемпотентность дневного тика** | daily catch-up гоняет N дней подряд; сервис вызван дважды за тик | каждый `SimulateDay(tick)` — чистая функция от состояния; `AdvanceToTick` монотонен; повтор того же дня — no-op | двойной `SimulateDay(sameTick)` не удваивает эффекты |
| I7 | **Кап на catch-up** | загрузка после долгого отсутствия → «перемотка войны» на 100 дней за тик | лимит смоделированных дней за тик (как существующий daily-cap); остаток — на следующих тиках | catch-up 500 дней не гонит 500 боёв в одном кадре |
| I8 | **Не двойное вождение** | параллельно активен Rim War **или** core-loop уже двигает те же армии/фракции | фичефлаг взаимоисключения с Rim War (детект `Torann.RimWar`); армии/фракции — один владелец действия за тик | флаг off при активном Rim War; армия с raid-резервацией не берётся world-war планировщиком |

## 1. R1 — Индекс мощи поселения (`SettlementPowerService`)

| Случай | Обработка |
|---|---|
| Поселение с **0 живого населения** (все Dead/Missing/Prisoner) | мощь = 0; поселение не может действовать; кандидат на коллапс фракции (I1) |
| Пленные/беженцы/мигранты | учитываются как в `FactionLifecycleService` (не Dead/Missing держат фракцию живой), но в **боевую** мощь идут только Alive-резиденты — иначе пленник «воюет» |
| Нет экономических данных (поселение без производства/ресурсов) | оснащённость → нейтральный множитель 1.0 (fail-open), мощь = только население |
| Огромное население | мощь ограничена разумным потолком/кривой (как ванильный `maxPawnCostPerTotalPointsCurve`), не линейно до бесконечности |
| Отрицательные/переполнение | clamp ≥ 0, целочисленно; никаких `float`-NaN |
| Пересчёт частоты | раз в день в тике, кэш; гейты/планировщик читают кэш, не пересчитывают (I4) |

**Проверить:** пустое поселение → мощь 0; пленник не добавляет боевой мощи; отсутствие экономики не роняет; детерминизм.

## 2. R2 — Behavior-архетипы (`FactionBehavior`)

| Случай | Обработка |
|---|---|
| Фракции **не назначен** behavior | дефолт (`Undefined`→нейтральный/`Random`), fail-open; не крешить |
| **Player / Vassal** фракция | исключены из world-war планировщика (не атакуют сами себя/игрока автономно) |
| **Excluded** (моды, спец-фракции) | полностью вне петли |
| **Не-людские** (мехи/инсекты/сущности) | гейт `humanlikeFaction` — нет behavior, нет мощи, ваниль (population-flow §2) |
| **Скрытые/безбазовые людские** (Ancients — люди без баз) | гейт «есть поселения»: нет поселений → не в петле (pass-through) |
| Фракции из модов (Empire/VFE) | behavior по дефолту, DLC/мод-гейтинг fail-open; не предполагать наличие |
| Игрок **сделал фракцию вассалом** в рантайме | смена behavior на лету учитывается на следующий тик |

**Проверить:** нет behavior → безопасный дефолт; player/excluded не действуют; не-людская фракция вне петли; смена behavior подхватывается.

## 3. R3 — Движение армий по карте (`ArmyMovementService`)

`WorldArmy` сейчас = `(Id, Name, FactionId, SourceSettlementId)`; членство = владение
(`_owners`). R3 добавляет позицию/цель/ETA — все новые поля back-compat (I5).

| Случай | Обработка |
|---|---|
| Армия с **0 членов** (все списаны/погибли в пути) | распускается, владение (если есть) возвращается; не «пустой призрак» ходит |
| **Цель уничтожена/захвачена** до прибытия | ретаргет (ближайшая валидная цель в range) или разворот домой; не бить несуществующее |
| **Источник (SourceSettlement) уничтожен** пока армия в пути | армия становится «бездомной»: при победе может осесть/основать; при отмене — ассимиляция/роспуск (перетоки, не удаление людей) |
| **Недостижимая цель** (океан, разрыв континента, world-wrap) | абстрактный `pathCost`/ETA в Core (без RimWorld-reachability); недостижимо → не выбирается как цель |
| Армия дальше **engagement range** | не выбирается (range по behavior, R2) |
| Две армии на одном тайле / встречный марш | детерминированный порядок разрешения (I2), бой при пересечении (R4) |
| Долгий ETA + daily catch-up | движение по дням с капом (I7); не телепорт |

**Проверить:** пустая армия распускается без потери людей; цель исчезла → ретаргет/возврат; бездомная армия не теряет граждан; детерминизм порядка.

## 4. R4 — Бой NPC-vs-NPC (`WorldBattleService`)

| Случай | Обработка |
|---|---|
| **Равные силы** | детерминированный тайбрейк (id/seed), не бесконечный клинч |
| **Защитник пуст** (0 боевой мощи) | поселение захватывается/разрушается без «фейкового» боя |
| **Атакующий вырезан** | армия распускается, потери = реальные граждане (I1), поселение защитника уменьшено |
| **Захват vs разрушение** | политика: захват → смена `FactionId` поселения + выжившие резиденты меняют принадлежность; разрушение → население→0, `FactionLifecycleService` при 0-living коллапсит фракцию |
| **Последний город фракции** пал, но её армия ещё в пути | коллапс фиксируется, когда у фракции 0 living **и** нет активных армий (иначе преждевременно) — согласовать с `FactionLifecycleService` |
| **Цель — поселение игрока** | НЕ тихий ledger-бой: маршрутизируется в **материализацию рейда** игроку (`LivingWorld_FactionRaid`, core-loop) — игрок видит бой на своей карте |
| **Атакующий и защитник — одна фракция** | guard: не бывает (союзники/своя фракция не атакуют) |
| Одновременные взаимные атаки A→B и B→A за день | разрешать в стабильном порядке, обе учесть; не потерять население дважды |
| Потери → дробное население | целочисленно, clamp ≥ 0; округление детерминированное |

**Проверить:** Σ населения не растёт после боя; захват меняет FactionId и сохраняет людей; разрушение → коллапс через lifecycle; удар по игроку идёт через инцидент, не тихо; тайбрейк детерминирован.

## 5. R5 — Планировщик действий (`FactionActionPlanner`)

Воспроизводит выбор из 6 `RimWarAction` (Warband/LaunchedWarband/Settler/Caravan/
ScoutingParty/Diplomat) по behavior и мощи — **своей** логикой (clean-room).

| Случай | Обработка |
|---|---|
| **Нет валидных целей** в range | действие `None` (ничего); не крешить, не бить пустоту |
| **Недостаточно мощи** на действие | накапливать; ничего в этот день |
| Фракция с **1 поселением** | оборонительный уклон; не отправлять последних бойцов в атаку, оголяя дом |
| Все соседи **союзники** | нет warband-целей → torговля/scout/diplomat/expand вместо атаки |
| `Settler`-экспансия | **переиспользует** `DrifterFoundingService`/`FoundSettlement`; не дублировать логику founding; не плодить поселения без людей |
| `Caravan` | **переиспользует** экономику Codex (trade ledger); не рисовать серебро из воздуха |
| `ScoutingParty` | питает существующий `RaidIntelService`/known-settlement intel; не отдельная теневая система |
| Пул действий урезан (`ActionTypesCount`-аналог) | нет settler если фракция не `createsSettlements`; нет launched если нет способности; корректно при 0 доступных → `None` |
| Детерминизм выбора | seed-взвешенный выбор, не `Rand` (I2) |

**Проверить:** нет целей → None; экспансия/торговля идут через существующие сервисы (не дубль); фракция не оголяет последний город; детерминизм.

## 6. R6 — Дипломатия (`DiplomacyService`)

| Случай | Обработка |
|---|---|
| **Пираты** (goodwill −100 навсегда) | не могут стать союзниками; дрейф не поднимает их выше враждебности |
| Отношения **с игроком** | ledger-дрейф **не** трогает ванильный goodwill напрямую по умолчанию; материализация в ваниль — консервативно/за флагом (не ломать ожидания игрока, §E) |
| **Скрытые/недипломатичные** фракции (мехи, инсекты, Ancients, культ) | вне системы отношений |
| Война двух фракций vs их goodwill | ledger-война понижает ledger-отношения; рассинхрон с ванилью допустим, пока не материализуем |
| Взаимоисключение с ванильным дрейфом goodwill | не дублировать: наш слой поверх, не спорить (аддитивно) |

**Проверить:** пираты не всплывают в союзники; отношения с игроком не портятся молча; скрытые фракции не участвуют.

## 7. R7 — Материализация / UI / фичефлаг

| Случай | Обработка |
|---|---|
| **Rim War активен** в модлисте | детект `Torann.RimWar` через `ModLister`; наш world-war loop **выключен** (I8); показать игроку, что делает Rim War, а не мы |
| Игрок **убрал Rim War** из сейва, где он был | ванильно осиротевшие RW world-объекты — не наша забота (их чистит игрок/RuntimeGC); мы не читаем и не зависим от них |
| **Тоггл флага в середине партии** | безопасно: наш слой — только ledger; включение начинает с текущего состояния, не «догоняет» задним числом |
| **Варбанды: абстрактные vs world-объекты** | по умолчанию **абстрактные** в ledger (дёшево, §I4); материализация world-объектами — за флагом позже (перф-риск на масштабе) |
| Main-tab/History рендер на масштабе | кап строк/кэш (как уже сделано для main-tab); не считать по полному состоянию каждый OnGUI |
| Локализация | все новые строки EN+RU (соглашение проекта) |

**Проверить:** флаг off при активном Rim War; тоггл в партии не крешит; UI капнут.

## 8. Взаимодействие с существующими системами LW (анти-дубль)

Самый тонкий класс — не подраться со своими же подсистемами за одни и те же данные:

| Система | Конфликт | Разрешение |
|---|---|---|
| **Рейды игроку** (planner/allocator/interceptor/binding/reconciliation) | world-war армия vs raid-резервация — двойное использование армии/граждан | у армии — **состояние/назначение** (raid-reserved vs world-move); планировщик не берёт зарезервированную под рейд; удар по игроку = именно рейд-путь (§4) |
| **Дрифтеры** (arrival/founding/assimilation) | `Settler`-экспансия vs drifter-founding создают поселения | одна точка `FoundSettlement`; экспансия тянет людей из поселения-основателя (перетоки), не из воздуха; не гонять обе за один пул |
| **Миграция** (`WorldMigrationGroup`) | военное перемещение vs миграционное давление | война — отдельный канал (армии), но беженцы от разрушенных поселений идут через существующую миграцию |
| **Экономика Codex** (production/trade/resource) | `Caravan`-действие vs trade ledger | `Caravan` вызывает существующий trade-путь, не свой |
| **Faction lifecycle** (collapse) | R4 разрушение → 0 living → коллапс | переиспользовать `SimulateCollapses`; согласовать тайминг «0 living И нет активных армий» (§4) |
| **Порядок в дневном тике** | R-сервисы + существующие (production/daily/demography/migration/drifter/collapse) | зафиксировать **единый порядок**: экономика→демография→миграция→drifter→**war(power→plan→move→battle)**→collapse; collapse последним |

## 9. Порядок дневного тика (предлагаемый, детерминированный)

```
SimulateWorldDay(day):
  1. SettlementProductionService        (Codex)
  2. SettlementDailySimulation (food/birth)
  3. DemographyService (aging/death)
  4. MigrationService
  5. Drifter: Arrival -> Founding -> Assimilation
  6. WAR (новое):  R1 обновить кэш мощи
                    R5 FactionActionPlanner (выбор действий)
                    R3 ArmyMovementService (движение, кап I7)
                    R4 WorldBattleService  (бои прибывших)
                    R6 DiplomacyService    (дрейф отношений)
  7. FactionLifecycleService.SimulateCollapses   (последним)
```
Обоснование: мощь и планы — до движения; бой — после прибытия; коллапс — в конце,
когда все убыли за день учтены (и с учётом «нет активных армий», §4).

## 10. Матрица тестов (must-have до «зелёного»)

- **Консервация:** для каждого разрушающего действия — Σ(Alive+Prisoner+Missing+Dead)
  инвариант; потери = списанным.
- **Детерминизм:** один seed, два прогона N дней → идентичные события/состояние.
- **Fail-open:** каждый worker/патч с null-компонентом/пустым ledger → ваниль.
- **Идемпотентность/кап:** `SimulateDay` дважды = один раз; catch-up 500 дней ≤ cap/тик.
- **Гейты:** не-людская/скрытая/player/excluded фракция вне петли.
- **Анти-дубль:** зарезервированная под рейд армия не движется world-war; экспансия/торговля идут через существующие сервисы.
- **Back-compat:** старый снапшот без war-полей грузится.
- **Взаимоисключение:** флаг off при `Torann.RimWar`.
- **Масштаб:** бенч 20k граждан — нет per-citizen прохода в гейтах; TPS-профиль.

## 11. Остаточные риски (принять/следить)

- **Масштаб 20k–100k** требует **компактной сериализации/когорт** (§C) — предпосылка,
  отдельный трек; без него war-слой утяжелит сейв.
- **Материализация ledger-фракций в RimWorld `Faction`** — остаётся за флагом (§11
  population-flow); новые фракции сперва как источники рейдов.
- **Совместимость с другими фракционными модами** (Empire, VFE-Insectoids) — гейты
  (humanlike, есть-поселения) должны их корректно исключать; перечислить в тестах.
- **Координация с core-loop** — R-фазы мержить после его влития; общая поверхность
  `WorldState`/армии/фракции.
