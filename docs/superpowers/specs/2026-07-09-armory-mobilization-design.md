# Арсенал / Мобилизация колонии — дизайн

Статус: **дизайн согласован, к ревью перед планом реализации.**

Подсистема активной карты (colony-AI), **только колония игрока**. Отдельна от
мировой симуляции Living World (ledger): здесь — постройки, состояние тревоги и
автономное поведение колонистов, а не глобальный мир. Может жить в той же сборке
мода отдельным модулем.

## 1. Цель

Колонисты в мирное время работают в гражданской одежде без оружия. При **боевой
тревоге** они сами идут в арсенал, берут своё снаряжение со стоек и экипируются;
после боя разоружаются и возвращают снаряжение на стойки; перед выходом в поход
(караван/рейд) сперва вооружаются. Кого мобилизовать и что дать — **с учётом
навыков**.

## 2. Согласованные решения

| Вопрос | Решение |
|---|---|
| Чьи пешки | Только колония игрока |
| Триггер | **Авто** (враги на карте / сработало предупреждение о рейде) **+ ручной** тумблер колонии |
| Модель снаряжения | **Гибрид**: назначенный набор → берёт его; иначе — скилл-подбор из пула |
| Навыки | Мобилизуются боеспособные; оружие под лучший навык |
| Автоматика | **Полная автономия** (конечная цель); строится фундамент → автономия |

## 3. Компоненты (единицы с чёткими границами)

### 3.1 MobilizationState (`MapComponent`, персистентный)
Единственный источник истины «мобилизовано ли». 
- Поля: `bool ManualMobilized`, вычисляемое `bool ThreatPresent`, итог `IsMobilized = ManualMobilized || ThreatPresent`.
- `ThreatPresent` = есть враждебная пешка на домашней карте (кэш, пересчёт по таймеру, не каждый тик).
- Персист через `ExposeData`. Fail-safe: ошибка расчёта → `ThreatPresent=false` (не запирать колонию в тревоге).

### 3.2 Стойки-арсенал (кастомные `Building_Storage`)
Три вида (как просил игрок): **стойка оружия**, **стойка брони**, **стойка одежды**.
- Реализация: `Building_Storage` с предустановленным фильтром категории (оружие / броня-апарель / гражданская одежда). Хранят боевые наборы в мирное время.
- Мирное время: боевое снаряжение лежит на стойках; гражданка — на колонисте или на стойке одежды.
- Def-ы + текстуры + рецепты постройки.

### 3.3 LoadoutSelectionService (ЧИСТАЯ логика, тестируемая)
Без побочных эффектов: `(навыки пешки, назначенный набор?, доступный пул) → выбор (оружие, броня)`.
- **Кто боеспособен:** `max(Shooting, Melee) >= CombatSkillThreshold` (по умолчанию 4, настраиваемо). Ниже — остаётся работать.
- **Оружие:** назначенный набор приоритетен; иначе — если `Shooting >= Melee` → лучшее доступное **дальнобойное**, иначе → лучшее **холодное**. «Лучшее» = по market value / качеству из пула.
- **Броня:** назначенная приоритетна; иначе — лучшая доступная под роль (милишникам-фронту тяжёлую при наличии).
- Детерминирована (сортировки стабильны, тай-брейки по defName) → юнит-тесты.

### 3.4 Автономный AI (`ThinkNode` + `JobGiver` + `JobDriver`)
Вставляется высоко в think-tree колонистов через `PatchOperation` на `ThinkTreeDef`
(над обычной работой, под драфтом/выживанием).
- `ThinkNode_Mobilized`: активен только при `IsMobilized`.
  - боеспособен + **не экипирован по набору** → `JobGiver_FetchKit`;
  - иначе → пропустить (пусть занимает оборону/работает как обычно).
- При `!IsMobilized` + пешка вооружена набором → `JobGiver_ReturnKit`.
- `JobDriver_FetchKit`: путь к стойкам → взять оружие (`Equip`) → надеть броню (`Wear`), сняв конфликтующую гражданку на стойку одежды.
- `JobDriver_ReturnKit`: снять оружие/броню → отхаулить на стойки → надеть гражданку.
- **Перед походом:** если пешка уходит в караван/рейд — форс `FetchKit` до отбытия (хук на формирование каравана).

### 3.5 UI
- **Тумблер колонии** «Мобилизация / Отбой» (гизмо/кнопка; показывает текущее состояние и причину — «враги на карте» / «вручную»).
- **Назначение набора на пешку:** вкладка/окно, где на колониста вешается оружие+броня как «его набор» (для гибрида). Без назначения — работает скилл-подбор.

## 4. Поток данных

```
угроза на карте  ──┐
ручной тумблер   ──┴─► MobilizationState.IsMobilized = true
                        │
                        ▼
        ThinkNode_Mobilized (на каждом боеспособном недрафченном колонисте)
                        │  не экипирован?
                        ▼
        JobGiver_FetchKit → JobDriver: путь→взять оружие→надеть броню (скилл/набор)
                        │
                     (бой)
                        ▼
        отбой (IsMobilized=false) → JobGiver_ReturnKit → вернуть на стойки, гражданка
```

## 5. Тестирование

- **LoadoutSelectionService** — детерминированные юнит-тесты (кто боеспособен, оружие под навык, тай-брейки, пустой пул, назначенный набор побеждает).
- **Структурные** — def-ы стоек, `ThinkTreeDef` PatchOperation, классы job'ов, гизмо, локализация EN/RU.
- **Reflection-verify** RimWorld API: `Pawn_EquipmentTracker.MakeRoomFor/AddEquipment`, `Pawn_ApparelTracker.Wear/TryDrop`, `JobDriver`, `Building_Storage`, `ThinkNode`, `Building`/`GenSpawn`.
- **Живой тест (обязателен для §3.4):** автономное поведение headless не проверяется — тюнится за компом.

## 6. Границы (YAGNI) — чего НЕ делаем в этой итерации

- NPC-поселения не мобилизуются (это отдельно, world-sim). 
- Не заменяем ванильный драфт/бой — только авто-экипировка вокруг него.
- Не строим полноценную loadout-систему уровня Compositable Loadouts — минимальный «набор = оружие + броня».
- Медикаменты/боеприпасы/сайдармы — вне первой итерации.

## 7. Риски и порядок реализации

**Главный риск:** автономные think-tree джобы воюют с ванильной системой работ и
драфта; смена одежды civvie↔броня капризна (слоты/части тела, конфликты апарели);
крайние случаи (пешка сбита во время похода за снаряжением, предмет исчез, стойка
недоступна). Всё — fail-safe: джоб не удался → пешка не застревает, ведёт себя как
обычно.

**Порядок (фундамент → автономия), даже при цели «полная автономия»:**
1. `MobilizationState` + ручной тумблер + UI-индикатор — состояние видно, проверяемо.
2. Стойки-арсенал (постройки) + `LoadoutSelectionService` (чистая логика + тесты).
3. Механика «взять/вернуть/переодеться» через явную команду или на драфт — надёжный экип/разэкип.
4. **Автономный слой** (`ThinkNode` авто-fetch по мобилизации) — требует живого тюнинга.
5. Вооружение перед походом + полировка.

Каждая фаза самодостаточна, TDD-покрыта где применимо, 0 warnings, EN/RU.

## 8. Итог

Автономная мобилизация колонии: мир — гражданка, тревога — арсенал по навыкам, отбой
— разоружение, поход — сперва оружие. Фундамент строится проверяемо; автономный AI —
последней фазой с живым тестом.
